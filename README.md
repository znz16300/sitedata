# sitedata — дані для сайту ліцею

Скрипт бере дані з Google Таблиць (новини, сторінки, документи, педагоги, розклад) і публікує їх як JSON
на `https://znz16300.github.io/sitedata/data/…`. Сайт читає ці файли.

```
Google Форма / Таблиця ──► publish.py (GitHub Actions, кожні 30 хв) ──► data/*.json, img-news/ ──► сайт
         ▲                                                    │
         └──── статус, show=1, нові посилання на фото ◄───────┘
```

**Що робить `publish.py`:**
- публікує лише дозволені колонки: email та інші особисті дані **ніколи** не потрапляють у JSON;
- для новин і оголошень ставить `show = 1`, якщо поле порожнє, і в JSON, і в самій таблиці. Щоб приховати новину, впишіть `0`;
- переносить фото з Google Drive в `img-news/`:
  - основне фото у WebP до 1600 px;
  - мініатюра 640 px для карток у полі `Мініатюри`;
  - для старих фото мініатюри створюються автоматично;
- дає кожній новині постійний `id` з «Позначки часу», тож посилання не «з'їжджають», якщо видалити рядок. Старий номер рядка зберігається в полі `n`, тому давні посилання `?id=5` теж працюють;
- перезаписує файл лише якщо дані змінились, і запитує Google Drive лише про нові документи;
- оновлює `data/photogallery.json`, нові фото йдуть першими;
- пише звіт про проблеми (наприклад, недоступне фото) у підсумок запуску на GitHub і в колонку «Статус публікації», якщо така є в таблиці.

## Автоматичне оновлення на GitHub (кожні 30 хв у робочий час)

Робиться один раз.

### 1. Ключ — у секрети GitHub
1. Відкрийте репозиторій **sitedata** на GitHub → **Settings** → **Secrets and variables** → **Actions**.
2. **New repository secret**:
   - Name: `GOOGLE_SERVICE_ACCOUNT_JSON`
   - Secret: відкрийте новий JSON-ключ у Блокноті, скопіюйте **весь вміст** і вставте.
3. **Add secret**. Після цього файл ключа на комп'ютері можна видалити або перенести в `secrets/` (див. «Ручний запуск»).

### 2. Дозволити роботу Actions
1. **Settings** → **Actions** → **General**.
2. **Actions permissions**: *Allow all actions and reusable workflows*.
3. **Workflow permissions**: **Read and write permissions** → **Save**.

### 3. Доступ сервісного акаунта до таблиць
Кожну таблицю з `config.json` має бути відкрито для email сервісного акаунта: поле `client_email` у JSON-ключі, вигляду `…@t-sunlight-247017.iam.gserviceaccount.com`.
- **Новини**: права **Редактор**, бо скрипт записує `show = 1`, нові посилання на фото і статус.
- Інші таблиці: достатньо **Читач**.

Скоріше за все, це вже налаштовано, бо старі скрипти працювали з тим самим акаунтом.

### 4. Завантажити файли й перевірити
1. Закомітьте й запуште цю версію репозиторію.
2. На GitHub: вкладка **Actions** → **Оновлення даних сайту** → **Run workflow** → **Run workflow**.
3. Через хвилину відкрийте запуск: зелена галочка означає, що все добре. У розділі **Summary** видно, що оновилось і які були проблеми.
4. Перевірте, що сайт показує свіжі дані. Зазвичай GitHub Pages оновлюється за 1–2 хв після запуску.

**Далі все працює саме**: пн–пт кожні 30 хв з 7:00 до 18:30 за Києвом (улітку з 8:00 до 19:30).
Розклад задано рядком `cron` у `.github/workflows/publish.yml`.

> **Корисно знати:**
> - GitHub може запускати за розкладом із затримкою 5–15 хв, особливо на початку години. Для термінової публікації є кнопка в таблиці.
> - Якщо в публічному репозиторії **60 днів немає жодних змін** (наприклад, улітку), GitHub вимикає розклад. Увімкнути знову: **Actions** → **Оновлення даних сайту** → **Enable workflow**.
> - Якщо запуск завершився з помилкою, GitHub надсилає лист власнику репозиторію.

## Кнопка «Опублікувати» в Google Таблиці

Дозволяє оновити сайт одразу, не чекаючи 30 хвилин, і за бажанням автоматично після кожної відповіді форми.

### 1. Токен GitHub (один на всі таблиці)
1. GitHub → аватар → **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**.
2. Token name: `sitedata-publish`. Expiration: до 1 року; поставте собі нагадування оновити.
3. **Repository access**: *Only select repositories* → `sitedata`.
4. **Permissions** → **Repository permissions** → **Actions**: **Read and write**. Більше нічого не потрібно: цей токен може лише запускати оновлення і не може змінювати файли.
5. **Generate token** і скопіюйте його (показується один раз).

### 2. Скрипт у таблиці
1. Відкрийте таблицю (наприклад, «Новини») → **Розширення** → **Apps Script**.
2. Замініть вміст файлу `Code.gs` вмістом `apps-script/Publish.gs` із цього репозиторію.
3. За бажанням вкажіть угорі `ONLY_TABLES = 'news'`. Тоді кнопка оновлює лише цю таблицю, і це швидше. Назви таблиць — поле `name` у `config.json`.
4. Збережіть (💾) і закрийте вкладку. **Оновіть сторінку таблиці**: з'явиться меню **🌐 Сайт**.
5. **🌐 Сайт → Налаштувати токен GitHub…**, вставте токен. Google попросить дозволи: погодьтесь. Якщо з'явиться «Google не перевірив цей застосунок», натисніть **Додатково** → **Перейти до…**
6. Для таблиці з відповідями форми: **🌐 Сайт → Публікувати автоматично після кожної відповіді форми**.

Повторіть пункт 2 для інших таблиць, де потрібна кнопка. Токен той самий.

## Щоденна робота

- **Нова новина**: заповніть форму. Сайт оновиться протягом 30 хв, або одразу, якщо ввімкнено автопублікацію чи натиснуто кнопку.
- **Приховати новину**: впишіть `0` у колонку `show`. Порожнє поле означає «показувати».
- **Фото не з'явилось**: найчастіше файл на Google Drive не відкрито. Відкрийте доступ «Усі, хто має посилання» або поділіться з email сервісного акаунта. Щоб бачити такі проблеми прямо в таблиці, додайте до таблиці новин колонку **`Статус публікації`**: скрипт пише туди «✅ опубліковано» або причину проблеми.
- **Фото з iPhone (HEIC)** обробляються автоматично.

## config.json

| Поле | Що задає |
|---|---|
| `public_base_url` | адреса, за якою GitHub Pages віддає цей репозиторій |
| `credentials_file` | де шукати ключ при локальному запуску (`secrets/service-account.json`) |
| `images` | розмір і якість фото (`max_size`, `quality`) і мініатюр (`thumb_size`, `thumb_quality`) |
| `never_publish_columns` | регулярні вирази назв колонок, які **ніколи** не публікуються (email, телефон…), навіть якщо їх вказати в `columns` |
| `tables[]` | таблиці для публікації (див. нижче) |
| `gallery` | куди писати фотогалерею |

Поля таблиці:

| Поле | Приклад | Що робить |
|---|---|---|
| `name` | `"news"` | коротка назва (для `--only` і кнопки в таблиці) |
| `id` | `"1Dk0…"` | ID Google Таблиці (з її адреси); ім'я JSON-файлу на сайті |
| `type` | `"rows"` / `"all_sheets"` | перший аркуш як список рядків / усі аркуші (розклади) |
| `columns` | `["Назва новини", …]` або `"*"` | які колонки публікувати (`"*"` — усі, крім заборонених) |
| `defaults` | `{"show": "1"}` | значення для порожніх клітинок |
| `write_defaults_to_sheet` | `true` | записувати ці значення і в саму таблицю |
| `photos_column` | `"Фото"` | колонка з фото: Drive → `img-news/` + мініатюри |
| `photo_folder_from` | `"Позначка часу"` | з якої колонки назва папки для фото |
| `stable_id_from` | `"Позначка часу"` | з якої колонки постійний `id` |
| `file_info_column` | `"Файл(и) документу"` | додати `info`/`type`/`size` файлу з Drive |

**Нова таблиця** = новий об'єкт у `tables` з `name`, `id`, `columns`. Відкрийте таблицю для сервісного акаунта, і з наступного запуску вона з'явиться на `…/sitedata/data/<id>.json`.

## Ручний запуск (на своєму комп'ютері)

Зазвичай не потрібен. Корисний для перевірки змін у `config.json`.

1. Покладіть JSON-ключ у `secrets/service-account.json`. Папка в `.gitignore`, ключ не потрапить на GitHub.
2. Запуск:
   - macOS/Linux: `./run.sh`
   - Windows: `run.bat`

   Скрипти самі створять `venv`, встановлять залежності, оновлять дані й запушать.

Корисні параметри `publish.py`:
```
python publish.py --list             # які таблиці налаштовано
python publish.py --only news        # лише новини
python publish.py --no-write-back    # нічого не змінювати в Google Таблицях (перевірка)
python publish.py --skip-images      # без завантаження фото з Drive
```

Важкі фото в `images/` (педагоги) і `photogallery/` можна стиснути без зміни назв:
`python tools/optimize_images.py images`.
